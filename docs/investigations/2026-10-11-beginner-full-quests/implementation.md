# 초보모드 전체 퀘스트·단계별 기능 해금 구현

구현·초안 작성: 2026-10-11. 최종 검토: **2026-10-12**. 구현 기준은 `f87c9666c5dd1ea35c6f9e67433cd19a797895da`이며 시작 시 로컬 HEAD, origin/main, 원격 main이 같고 working tree가 비어 있었다. 별도 기존 worktree는 보호했다. 커밋·push·배포·운영 DB 변경은 하지 않았다. 코드 구현과 주요 자동검증 이후 초안을 작성했고, 10월 12일 요구사항 대조·최종 검사·산출물 검토를 반영해 확정했다. 검토 전용 [종합 감사](../2026-10-11-prelaunch-audit-2/report.md)는 별도 결과다.

## 구현 결과

공통 6개 퀘스트는 순차 진행한다. 현재 실습 기능은 완료 전부터 사용할 수 있고, 이전 기능은 유지한다. QUEST 06의 서버 완료가 확인되면 모든 학습 제한이 해제된다. 한국주식·미국주식·선물 롱·숏은 서로 독립적이다. 서버 운영 플래그·시장시간·시세·계정 상태·위험 검증은 해금과 별개로 적용한다.

일반·시즌계정은 학습 검사에서 제외한다. 시세·자산 조회, 계정 전환, 기존 주문/보호 취소, 현물 매도, 선물 축소·종료는 학습 제한을 받지 않는다. 잠긴 기능도 화면에 표시하며, 채도를 낮춘 버튼/아이콘과 작은 자물쇠, 접근성 상태·조건을 제공한다. 평상시 아이콘 옆에 잠금 문구를 반복하지 않는다. 진행도 조회 오류는 학습 미완료로 표시하지 않고 재조회 안내를 제공한다.

`beginner-learning-policy.ts`가 읽기 전용 `BeginnerQuestEvidence`를 재사용한다. 소유권 확인 뒤 실행하고 실제 금융 명령의 기존 DB fence 안에서도 검사한다. 일반·시즌과 위험 축소는 조기에 제외한다. 커밋된 명령 재생은 기존 정책을 보존한다.

진행도 GET은 RepeatableRead 조회이며 금융 행·보상·계정을 만들지 않는다. 기존 FX/이체, Order, ProtectionGroup/Leg, FuturesExecution/Position/ExecuteRequest를 재사용한다. 새 금융 원장이나 퀘스트 엔진을 만들지 않았다.

금융 기록으로 증명할 수 없는 Q03 보유종목 확인과 Q06 주문 결과 확인만 `BeginnerQuestAcknowledgement`에 저장한다. 계정+step당 최초 한 행, 두 step만 허용하는 CHECK, 계정 및 주문의 복합 FK를 둔다. POST `/api/v1/trading-accounts/:accountId/quests/acknowledgements`는 선행 완료·주문 소유권·실제 체결/취소·예약 해제를 확인하고 계정 잠금 후 DB 시각을 기록한다. 재시도/다시하기가 완료 상태를 초기화하지 않는다. UI 확인은 사용자의 확인 의사이며 실제 화면을 보았음을 금융 증거로 주장하지 않는다.

## UI와 영향 범위

기존 QuestGuideProvider/모델/bridge, Shimmer+Glow, 스포트라이트, 완료 배지·폭죽·자동 복귀를 확장했다. 시장 목록 → 종목 상세 → 주문/보호/선물 → 실제 성공 응답 → 서버 재확인 흐름이다. 재실행은 실제 명령을 수행하되 폭죽 없이 복귀한다. 이전 성공 기록 재조회만으로 폭죽을 반복하지 않는다. 계정·세션·실습 ID와 명령 콜백을 묶어 늦은 응답을 분리했다.

보유수량이 사라진 Q04/Q05에는 시장가 매수로 다시 준비하는 안내가 있다. 주식 휴장·시세 미준비·운영 중지는 기존 화면 상태를 유지하며 다른 심화 실습으로 돌아갈 수 있다. 선물에는 낮은 레버리지·격리마진, 청산가격·UPNL, 기존 반대 포지션 정리 안내가 있다. 매도 예상 수령액 안내는 매도 수수료를 차감한다. 서버 계산식은 변경하지 않았다.

작은 화면의 지정가 입력 화면에서 호가 영역이 주문 버튼을 덮던 실제 클릭 문제를 발견해 세로 배치의 flex basis를 내용 높이로 유지했다. 주문 입력 방식과 안전장치는 그대로다.

변경 영역은 backend의 계정 퀘스트/금융 진입 검사/Prisma migration·생성 타입/관련 테스트, frontend의 퀘스트 및 실제 시장·자산·주문·지갑·보호·선물 화면/권한 표시/캐시 무효화/테스트다. 전체 **84개 구현 파일**의 정확한 목록과 해시는 [manifest](evidence/implementation-manifest.json)에 있다. 추적 파일 65개의 [diff](evidence/tracked.patch)와 새 파일 19개의 [diff](evidence/new-files.patch)를 함께 제공한다. 문서 계약은 `backend/docs/beginner-mode.md`와 README에 반영했다. 감사가 시작된 뒤 구현 소스는 변경하지 않았다.

## 운영 적용 전 확인

로컬 설정 파일에 해당 세 운영 플래그의 명시적 override가 없고 기본값은 `LIMIT_ORDER_ENABLED=false`, `CONDITIONAL_ORDERS_ENABLED=false`, `FUTURES_TRADING_MODE=DISABLED`다. 실제 배포 환경의 injected env는 이번 작업에서 조회하지 않았다. 기능 플래그를 켠 것은 격리 테스트 프로세스뿐이다.

따라서 **기본 운영 설정에서는 Q04와 Q06, 선물 실습이 제한된다.** Q06 완료 후에도 운영 중지 기능을 강제로 사용할 수 없다. 신규 migration을 배포 절차로 적용한 뒤 조건부·지정가와 각 매칭/위험 엔진·시세 수집기 준비를 확인해야 한다. 활성화나 배포는 이번 작업에 포함하지 않았다. Native 실기기, 실제 공급자·휴장 시간대 체험, 스크린리더 검증이 필요하다.

`git diff --check` 통과. 금융 수수료·PnL·마진·시장시간·원장 구조의 계산 정책을 바꾸는 diff, 보상/계정 초기화, 테스트 삭제, 무관한 리팩터링은 없다. 신규 상태는 UI 확인 두 행만이며 생성된 Prisma 파일은 그 스키마 변경에 따른 것이다. 종합 감사에서 발견한 기존 결함은 [별도 보고서](../2026-10-11-prelaunch-audit-2/report.md)에 기록했다.

## 최종 검토와 완료 범위 — 2026-10-12

원본 요구사항과 금융 증거·실행 경계·실제 화면 연결을 다시 대조했다. Q01/02 기존 근거, 기초 순서, 현재 실습의 사용 권한, Q06 해금, 심화 독립성, 위험 축소 예외, 계정/세션 분리, 안내 필수 문구와 접근성 라벨을 확인했다. 이 검토에서 추가 구현 수정이 필요한 퀘스트 회귀는 발견되지 않았다.
