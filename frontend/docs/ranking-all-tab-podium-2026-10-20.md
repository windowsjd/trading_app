## 1. 전체 탭은 내 행에서 시작

- 첫 페이지 = `scope=all&anchor=me&limit=50` (발행본 `rankingDate`/`capturedAt` 고정). 서버가 같은 스냅샷에서
  **공개 행 중 내 위의 수**(제외·랭킹 숨김 참가자는 세지 않음, `rank - 1` 아님)를 offset으로 정해 내 행부터 돌려준다.
  `pagination.offset`이 이 구간의 시작이다. 내 행이 없으면(미참가·숨김·제외·최종 자격 미충족·행 미생성) 1위부터, 예전과 같다.
- 배치: 첫 페이지가 그려지면 내 행을 화면 맨 위로 스크롤(헤더 = 내 순위 카드·순위 안내·시상대·탭은 그 위로 밀려남,
  내 행 테두리가 보이도록 8 여유). 그다음 바로 위 한 페이지(최대 50행, `offset − 50`)를 읽는다.
- 위로: 읽은 구간의 맨 위에서 화면 2개 이내로 올라가면 그 위 한 페이지. iOS/Android는
  `maintainVisibleContentPosition: { minIndexForVisible: 0 }`(헤더는 VirtualizedList가 +1로 셈)이 보고 있던 행을 제자리에
  둔다. 한 번에 한 페이지, 배치 전에는 읽지 않음, 그리고 위 페이지가 도착한 뒤에는 **다시 위로 스크롤할 때까지** 다음 페이지를
  읽지 않는다 — 위치를 유지하지 못하는 환경에서 목록이 스스로 끝없이 위로 읽는 것을 막는다.
- 아래로: 기존 `onEndReached`/`nextOffset` 그대로.
- 다시 전체 탭으로 오면, 새 발행본이 오면 → 새 구간(쿼리 키에 `시작:nonce`)으로 내 행에서 다시 시작. 두 스냅샷의 행이 섞이지
  않는다(모든 페이지가 첫 페이지의 `capturedAt`을 고정, `RANKING_SNAPSHOT_CHANGED` 복구 그대로).
- 친구·TOP10: 조회·정렬·목록 동작 변경 없음(anchor·위치 유지·위쪽 로딩·버튼 없음).

## 2. 맨위로 · 맨아래로

- 전체 탭 목록이 있을 때만, 화면 오른쪽 아래(아래 16·오른쪽 6)에 세로로 위·아래. 지름 36 원형(테두리 border, 바탕 surface,
  아이콘 secondary), 터치 48(hitSlop 6), 이중 화살표 SVG만(글자 없음), 접근성 이름 `맨위로`/`맨아래로`.
- 맨위로: 읽은 구간이 1위부터면 그냥 0으로 스크롤. 아니면 **첫 페이지만** 새 구간으로 읽고 맨 위(헤더+시상대+1위).
- 맨아래로: 읽은 구간이 끝까지면 끝으로 스크롤. 아니면 **마지막 페이지만**(`total − 50`, 발행본 total) 읽고 측정된 끝으로
  스크롤(목록 자체 `scrollToEnd`는 아직 안 그린 행을 추정해 모자랄 수 있음). 행 측정이 끝날 때까지 1.5초 동안 끝을 따라가고,
  사용자가 끌기 시작하면 멈춘다.
- 비활성: 맨위로 = 구간이 1위부터이고 스크롤 0, 맨아래로 = 구간이 마지막 행까지이고 끝까지 스크롤. 로드된 페이지의 첫/끝 행은
  경계로 보지 않는다. 스크롤할 것이 없으면 둘 다 비활성(투명도 0.4), 비활성은 아무 조회·이동도 하지 않는다.
- 목록 아래 여백 24 → 104(버튼 2개+간격+여유): 끝까지 내리면 마지막 행이 버튼 위에 온다. 스크롤 중에는 버튼이 지나가는 행
  오른쪽 숫자 일부 위에 떠 있을 수 있다(떠 있는 버튼의 성질; 36·오른쪽 6으로 최소화).

## 3. TOP 3 시상대

- 데이터: 기존 발행본 조회(`scope=all&limit=3&offset=0`, 같은 시즌·daily/final·스냅샷)의 첫 세 행 — 추가 조회 없음, 모든 탭에서
  같음. 1·2·3위가 정확히 첫 세 행일 때만(서로 다른 참가자, offset 0, available) 그린다. 2명 이하, 순위 공백(숨김 참가자로
  1·2·4), 로딩 중이면 아무것도 그리지 않는다(스켈레톤·문구 없음). `나`는 참가자 id로 판정.
- 위치: 순위 안내 행(없으면 내 순위 카드) 아래, 탭 위. 위 16(앞 요소의 아래 12 + 위 4) / 아래 16, 콘텐츠 폭은 목록과 같다.
- 표시 전용: 누를 수 있는 것 없음. 스크린리더에는 카드 하나로 `1위 …, 수익률 …, 티어. 2위 …. 3위 …` 순서(화면은 2·1·3).
- 사양 대응: 카드 surface/border/16/`overflow hidden`/패딩 22·10·0(라이트에서 #FFFFFF·#E5E8EB 그대로), 1위 뒤 방사형 조명
  (react-native-svg `RadialGradient` 300×110, 중심 위·가운데, #F0C95C 30%→0), 3열 같은 폭·간격 4·하단 정렬·`minWidth 0`.
  아바타 56/48(기존 `ProfileAvatar`, 바탕 #E6E9EE·테두리 없음 — `frameStyle` 선택 prop 추가, 기본값 불변), 링은 box-shadow
  대신 바깥 겹테두리(카드색 2 + 순위색 2: #D6A935/#AEB6C3/#CF9566). 왕관 26×16, 아바타 기준 left 15·top −18, 경로·

  단상·링·왕관·조명 색은 사양 그대로.

## 4. 웹(RN-Web) 한계

react-native-web 0.21에는 `maintainVisibleContentPosition`이 없다(ScrollView·vendored VirtualizedList 모두). 그래서 웹에서는
위 페이지가 도착하면 화면이 그만큼 바뀐다 — 웹은 배치 직후 위 페이지를 미리 읽지 않고, 사용자가 위로 스크롤할 때 한 페이지씩
읽는다(폭주 없음). iOS/Android의 위치 유지는 RN 0.83 구현에 의존하며 이 저장소 환경에서 실기기 확인은 하지 못했다.
