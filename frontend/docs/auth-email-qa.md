## 2026-10-19 UI·운영 회귀

- 가입/재설정 모두 최초 일반화 발송 응답 전에는 발송 버튼, 응답 성공 후에는 확인·재발송만 표시한다. 발송 실패는 최초 버튼에서 재시도한다.
- 잘못된 번호는 재입력을 허용한다. 서버의 만료/횟수 초과 응답이면 확인을 막고 재발송을 안내한다. 만료 뒤에도 최초 버튼은 나타나지 않는다.
- 재발송 시도 즉시 이전 증거를 폐기하고 이전 코드를 차단한다. 실패/응답 유실에도 발송 단계로 돌아가지 않으며, 보수적인 로컬 60초 대기 뒤 재발송한다. 서버 예산은 항상 최종 권위다.
- 인증 성공은 확인·재발송을 숨기고 회원가입/비밀번호 변경 버튼을 표시한다. 서버가 증거를 거부하면 재인증을 안내하며 재발송 단계로 돌아간다. 비밀번호 변경 완료는 DB 성공 뒤에만 표시한다.
- 이메일 변경과 왕복 변경 중 늦은 발송/검증 응답을 폐기한다. 연타는 단일 요청으로 제한한다.
- 로그인 아래 왼쪽 회원가입·오른쪽 비밀번호 찾기를 같은 너비/높이로 표시한다. 이메일 초기값 전달 및 기존 로그인 대기 상태(로그인·비밀번호 찾기 비활성, 회원가입 진입 가능)를 유지한다.
- 기존 Auth 타이머에서 시간당 각 500행까지 정리한다. 24시간 보존, 유효 코드/증거/예산 보존, SKIP LOCKED·동시 실행·실패 롤백을 격리 PostgreSQL에서 확인했다.
- Resend 수락/거부/timeout/network와 설정 disabled/invalid를 고정 진단으로 구분한다. 로그 장애가 결과에 영향을 주지 않는지, 민감정보가 없는지 mocked fetch로 확인했다.
- 프런트 인증 관련 10개 파일 PASS, 백엔드 관련 84 tests PASS, 인증 DB 68 grouped checks PASS, 회원탈퇴 DB 26 checks PASS. 전체 프런트 **246개 파일 PASS**. 누적 시간 제한으로 종료된 실행의 취소/미완료 파일만 실제로 이어 검증해 162 + 44 + 40개 전체 목록을 대조했다. 단일 실행 성공과 분할 완료를 구분한다.

## 레이아웃 검증 범위

실제 화면·Hook·테마·버튼을 기존 RN Web/Chromium 도구로 렌더링했다. 한글 NanumBarunGothic을 로컬로 제공하고 외부 API를 차단했다.

- 폭 320 / 375 / 430px × Light / Dark × 글꼴 1 / 2배.
- 로그인, 가입/재설정 최초·발송 중·코드/긴 오류·420px 키보드 모의 높이·만료·재발송 중·응답 유실·인증 완료, 비밀번호 변경 중·완료의 **228 사례 PASS**.
- 가로 넘침·글리프 잘림·가림 검출 0, 페이지 오류 0. 검출기는 의도적 nowrap/큰 글씨로 실패하는지도 확인했다.
- 로그인 보조 버튼의 동일 너비·높이·상단 정렬·주 버튼 양쪽 끝 정렬과 겹침 없음을 수치로 확인했다. 320px/2배는 두 버튼 모두 **130×104px**다. 줄바꿈을 허용하고 접근성 글꼴 배율을 제한하지 않는다.
- 최초 발송·재발송 대기 중 버튼 높이 불변, 스크롤과 버튼 접근을 검증했다. Android/iOS 모의 키보드 이벤트 테스트는 최초·코드 확인 단계의 입력과 액션을 함께 노출하는지 확인했다.

## 실기기 및 실제 메일 검증 — NOT_RUN

Android/iOS 기기와 승인받은 수신 주소가 없어 아래 항목은 NOT_RUN이다.

1. 320/375/430px에 준하는 기기에서 Light/Dark, OS FontScale 1/2로 모든 단계 확인.
2. Android 숫자 키패드·이메일/비밀번호 키보드 및 iOS 키보드에서 입력·확인·재발송·스크롤·뒤로가기 확인.
3. 긴 오류/큰 글씨/작은 화면에서 하단 버튼까지 접근하고 입력값·타이머가 겹치지 않는지 확인.
4. 백그라운드 복귀 후 만료·재발송 제한, 앱 종료 후 새 인증 필요, 뒤로가기 중 늦은 응답 확인.
5. 승인된 이메일 한 주소로 회원가입/재설정 실메일 수신, 제목·발신자·HTML/text·스팸함·코드 만료 확인.
6. 두 기기로 로그인 → 한 기기에서 재설정 → 두 기기의 이전 보호 API/Refresh 거부 및 새 비밀번호 재로그인 확인.
7. 서버 연결 실패·요청 시간 초과·메일 제공자 장애에서 완료 오표시가 없고 재시도 안내가 가능한지 확인.

단위 테스트의 키보드 이벤트/측정 모의 검증은 Android/iOS에서 기존 스크롤 동작을 보존하지만, 실제 키보드 검증은 위와 같이 NOT_RUN이다.

## 릴리스 순서

1. Resend에서 `nanghwa.com` 발신 도메인 검증과 발송 권한/한도 확인. 승인된 수신 주소 확보.
2. 운영 변경 승인 후 migration `20261018120000_auth_email_verification` 적용. 기존 이메일 인증 시각은 null, 토큰 버전은 0이다.
3. backend에만 `RESEND_API_KEY`, `EMAIL_FROM="Trading Class <admin@nanghwa.com>"`, 32자 이상 랜덤 `EMAIL_VERIFICATION_SECRET` 설정. 모든 서버에서 같은 값을 사용한다.
4. 실제 ingress를 확인한 뒤 `AUTH_TRUST_PROXY_HOPS` 설정. 기본 0이면 프록시 뒤 모든 요청이 같은 IP 제한에 묶일 수 있다.
5. 전환 중 이전 서버로 무인증 가입이 통과하지 않게 가입 ingress를 잠시 제한하거나 서버를 일괄 교체한다. 모든 인스턴스에 증거 검증·토큰 버전 Guard가 있는지 먼저 확인한다.
6. 새 API 제공 후 Expo 업데이트 채널/runtimeVersion 정책에 맞춰 앱 배포. 새 네이티브 라이브러리는 추가하지 않았다. EAS 빌드/업데이트 실행은 별도 승인 대상이다.
7. 구버전 앱의 기존 로그인/Refresh는 유지된다. 구버전 회원가입은 인증 증거가 없어 실패하므로 업데이트 안내/최소 지원 버전 정책을 릴리스 전에 준비한다. 우회 API는 두지 않는다.
8. 실제 메일 및 위 기기 QA 후 가입 제한을 해제한다. 롤백 시에도 인증 증거 검사와 버전 Guard를 제거하지 않는다.

만료 인증 정리는 기존 Auth 유지보수 타이머에 연결되었다. 새 환경변수·migration·별도 워커·큐·외부 cron은 필요하지 않다. 배포 후 고정 cleanup 이벤트의 건수·실패를 확인한다. 운영 프록시 hop/헤더 덮어쓰기 확인과 실제 메일·실기기 검증은 별도 수행한다.
